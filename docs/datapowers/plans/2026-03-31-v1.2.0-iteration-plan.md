# datapowers v1.2.0 迭代计划

**日期**: 2026-03-31  
**基准版本**: v1.1.0  
**参考来源**: gemini-idea.md V2.0 第 8 节（V3.0 提案）

## 专业评估：哪些建议值得采纳

**8.1 Analysis Manifest** — ✅ 采纳，但范围收窄

Gemini 提出 `analysis_manifest.json` 作为"单一真理来源"，追踪从 brainstorming 到 model-evaluation 的全链路状态。这个方向是对的——长程分析中上下文漂移是真实痛点。

但"当 model-selection 引入未在 brainstorming 讨论的变量时自动触发 `NEEDS_RE-BRAINSTORMING`"这个机制**过度工程化**：SKILL.md 系统本质上是无状态的，没有跨 session 的程序化变量追踪能力。可行的做法是：让 agent 在每个技能阶段写入 manifest，由下一个技能读取并校验，而不是自动拦截。

**8.2 Data Visual Companion** — ❌ 拒绝"自动反馈回路"，保留可视化生成

"用户标记图表中的异常 → 自动转化为 DM_SPEC.md 约束"是伪命题——skills library 没有 UI 基础设施，这个功能需要完整的 web 应用才能实现。不应纳入核心库。

可视化代码生成本身已在 `data-exploration` 里覆盖了，无需新建技能。

**8.3 Feature Lineage & Registry** — ✅ 采纳，升级现有 feature registry

v1.0 的 feature-engineering 已有轻量级 feature registry，但缺少：
- 业务动机字段
- 目标变量互信息（Mutual Information）分数
- 与 leakage-guard 的联动（registry 作为泄漏审计的一手证据）

这三点都有实际价值，且在 SKILL.md 框架内完全可实现。

**8.4 Writing-Data-Skills 元技能** — ✅ 采纳

与 superpowers 的 `writing-skills` 完全对应。"Statistical Pressure Test"（在 1:1 / 1:100 / 1:1000 三种不平衡场景下验证技能行为）是务实的质量门控。这也是项目长期健康发展的基础设施。

**8.5 Statistical Sovereignty** — ⚠️ 部分采纳

Bootstrap CI 和显著性检验已在 model-evaluation + statistical-reviewer + report-writing 里强制要求。真正缺的是：**多重比较校正（Bonferroni / BH）在 subgroup analysis 和 feature selection 场景中的强制性**。不需要新建技能，只需更新 statistical-reviewer。

**第 3 节 MLflow + DVC** — ❌ 不纳入铁律

MLflow 需要运行中的 tracking server，DVC 需要 remote storage 配置，都是重依赖。强制要求会让轻量级项目无法使用 datapowers。保留为 model-evaluation 和 report-writing 里的"推荐实践"，不升级为铁律。

## 具体工作项

### 工作项 1：`analysis-manifest` 技能（新增）

**目标**：解决长程分析的上下文漂移问题。

在分析开始时创建 `artifacts/analysis_manifest.json`，包含：
- 来自 brainstorming 的三条假设
- 声明的评估指标和基准线
- 已完成阶段的时间戳和 git commit hash
- 各阶段产物路径（profile、schema、feature registry、model artifact）

每个下游技能（data-exploration、feature-engineering、model-selection）在执行时读取 manifest 并追加本阶段记录。这样即便 session 中断，下次恢复时 agent 能看到完整进度，而不是从头问用户。

**不实现的部分**：自动变量拦截（太复杂，误报率高）。

---

### 工作项 2：`feature-engineering` 技能升级（更新现有）

**目标**：将 feature registry 升级为可审计的特征血缘资产。

当前 registry 只记录特征名称和类型。升级后每条记录必须包含：
- `business_motivation`：一句话说明该特征的业务动机（无动机 = 不允许创建）
- `transformation`：数学变换描述（非代码，是人类可读的逻辑）
- `mutual_information`：与目标变量的 MI 分数，training set 上计算
- `leakage_status`：`cleared` / `pending_review` / `blocked`

leakage-guard 在审计时**以 registry 为一手证据**：registry 中没有登记的特征，一律视为 `pending_review`。

---

### 工作项 3：`statistical-reviewer` 更新（更新现有）

**目标**：补全多重比较校正的强制检查。

在现有 P-hacking 检测基础上，新增：
- 当 subgroup analysis 涉及 ≥ 3 个子组时，必须确认使用了 Bonferroni 或 BH 校正
- 当 feature selection 基于统计检验时，必须确认 p-value 经过多重比较调整
- 当报告多个模型比较结果时，必须确认使用了 Wilcoxon signed-rank（而不是多次 t-test）

---

### 工作项 4：`writing-data-skills` 元技能（新增）

**目标**：为贡献新技能提供质量标准，与 superpowers 的 `writing-skills` 对等。

核心内容：
- 数据科学技能的必要结构（Iron Law、Hard Gate、Step-by-Step、Self-Review Checklist、Anti-Patterns）
- **Statistical Pressure Test 协议**：每个新技能必须通过三种数据场景的对抗测试——平衡数据（基础）、极度不平衡（1:100）、小样本（n<200），验证技能在每种场景下是否给出正确指导（而不是退化为"随便试试"）
- 技能命名和触发词规范（避免与现有技能重叠）
- Iron Law 撰写规范（必须是可操作的、可违反的具体禁令，不能是模糊的原则）

---

### 工作项 5：`data-profiling` 技能修订（更新现有）

**目标**：对齐 gemini-idea 6.1 中的两个被遗漏的细节。

当前 data-profiling 已实现大部分，但缺少：
1. **隐藏空值识别**：识别字符串型空值伪装（`"Unknown"`, `"N/A"`, `"None"`, `"-"`, `"null"`），在画像中标记为 `HIDDEN_NULL`，区别于真正的 `NaN`
2. **Target Correlation Top 10**：当目标列已知时，在 profile 中增加与目标列相关性最高的 Top 10 特征排名（数值用 Pearson / Spearman，分类用 Cramér's V）

这两点对子 Agent 的代码质量影响显著，且实现成本低。

## 优先级排序

| 优先级 | 工作项 | 理由 |
|--------|--------|------|
| P0 | `data-profiling` 修订（工作项 5） | 改动小，收益即时，子 Agent 直接受益 |
| P0 | `feature-engineering` registry 升级（工作项 2） | leakage-guard 依赖它；不升级则血缘审计无法闭环 |
| P1 | `statistical-reviewer` 多重比较（工作项 3） | 补全现有审查盲区，改动集中 |
| P1 | `analysis-manifest` 技能（工作项 1） | 解决长程分析核心痛点 |
| P2 | `writing-data-skills` 元技能（工作项 4） | 项目长期健康必要，但不阻塞当前用户使用 |
